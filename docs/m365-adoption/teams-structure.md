Recomendaciones de estructura de Teams

Resumen
Proponer una estructura de Teams que soporte gobernanza, colaboración y facilidad de gestión. Usar plantillas para equipos recurrentes (proyectos, operaciones, comités) y reglas de naming.

1) Plantillas de equipo (Team templates)
- Proyecto (Project): Canales: General, Planificación, Tareas, Documentos, Reuniones, Entregables. Aplicar pestañas: Planner, SharePoint, OneNote, Power BI.
- Operaciones / Soporte (Ops): Canales: General, Incidentes, Cambios, Documentación, Automatizaciones. Pestañas: Lista de SharePoint, Power Automate, Runbooks.
- Comité / Steering: Canales: General, Agenda, Actas, Decisiones. Pestañas: OneNote, SharePoint.
- Equipo HR / Personas: General, Anuncios, Políticas, Reuniones.

2) Canales estándar y privados
- Usar canales estándar para trabajo abierto; canales privados sólo para información sensible o miembros limitados (ej. revisiones salariales, asuntos legales).
- Evitar crear demasiados canales; preferir hilos y pestañas para organización.

3) Estructura de carpetas en SharePoint
- Cada canal -> carpeta en la biblioteca de documentos del equipo
- Plantillas de metadata (document type, project id, sensitivity)

4) Naming conventions
- Teams: <Org>-<FunctionalArea>-<Name> (ej. SIGE-Proyecto-PortalClientes)
- Canales: usar nombres cortos y convenciones predefinidas (General, Incidentes, Entregables)

5) Ciclo de vida y gobernanza
- Plantilla de creación que incluye: propietario, contactos, clasificación de datos, período de retención propuesto.
- Revisión trimestral de equipos inactivos para archivado.
- Roles: Team Owner, Team Member, Data Steward.

6) Plantillas para canales recurrentes
- Plantilla de canal de "Incidentes": pestañas de Lista de Incidentes (SharePoint), Power Automate para notificaciones, Plantilla de informe (Word/OneNote).

7) Buenas prácticas
- Establecer Owner obligatorio al crear equipo
- Aplicar sensibility labels si la organización usa MIP
- Habilitar políticas de guest access según necesidad

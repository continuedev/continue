Ready-to-use MCP server configurations for popular tools and services. Copy these into your `config.yaml` to get started.

MCP servers are only available in **agent** mode. For configuration concepts and setup details, see the [MCP deep dive](/customize/deep-dives/mcp).

## Sentry

Sentry's MCP server provides tools for querying issues, viewing stack traces, and searching events.

**Remote (SSE)**:

```yaml
mcpServers:
  - name: Sentry
    type: sse
    url: https://mcp.sentry.io
```

**Local (stdio)** — requires an auth token:

```yaml
mcpServers:
  - name: Sentry
    command: npx
    args:
      - "-y"
      - "@sentry/mcp-server@latest"
      - "--transport"
      - "stdio"
    env:
      SENTRY_AUTH_TOKEN: ${{ secrets.SENTRY_AUTH_TOKEN }}
```

See also: [Sentry MCP Error Monitoring guide](/guides/sentry-mcp-error-monitoring)

## Suno by Ace Data Cloud

Suno music tools through your own Ace Data Cloud account. Provided by Ace Data Cloud, not an official Suno integration.

```yaml
mcpServers:
  - name: Suno by Ace Data Cloud
    type: streamable-http
    url: https://suno.mcp.acedata.cloud/mcp
    requestOptions:
      headers:
        Authorization: Bearer ${{ secrets.ACEDATACLOUD_API_TOKEN }}
```

Inspect the MCP tools first. `suno_generate_music` can submit a billable operation; save its task ID and query `suno_get_task` with that same ID until a terminal result. Do not rerun generation to check progress.

Source and full API contract: [SunoMCP](https://github.com/AceDataCloud/SunoMCP).

## Set up the Ace media examples

The five entries above are independent service configurations; add only the service you intend to use. They are examples for local MCP configuration, not Continue Hub search/install listings.

1. [Register or sign in → Ace Data Cloud Applications](https://platform.acedata.cloud/console/applications?utm_source=continue&utm_medium=integration&utm_campaign=ecosystem-growth&utm_content=media_examples_api_key).
2. Open **General application** or choose **Initialize General Application**. Copy the API Key, or use **Manage Keys → Create** for a separate token named for Continue and the service.
3. Review service access, expiration, allowed generation **and task-query** APIs, usage limits and [current pricing/balance](https://platform.acedata.cloud/models?utm_source=continue&utm_medium=integration&utm_campaign=ecosystem-growth&utm_content=media_examples_pricing). No free generation allowance is implied.
4. Save the raw token as `ACEDATACLOUD_API_TOKEN` in your private `~/.continue/.env`. Do not use a `platform-...` management token or commit the secret. Keep the YAML placeholder unchanged.
5. Reload Continue and inspect the service's tool list in Agent mode with a tool-capable model. A loaded list confirms connection, not a completed generation or a correct bill.

![Create a dedicated token](https://raw.githubusercontent.com/AceDataCloud/SunoDify/8d3d03570e73324220f111f7fe343da0792a8071/_assets/tutorial/create-api-key-en.png)

These redacted Ace account screenshots are reused from its published Suno for Dify guide; they show shared account Key controls, not a Continue run. Use the existing [Continue local configuration entry](/customize/deep-dives/configuration) and keep real credentials out of captures. Each service supports its own current models, task states, result fields and price; inspect its tool schema and linked source rather than assuming identical payloads.

401 errors require checking the token and access; 403 can be permissions or moderation. Pending/preview responses are not final media. Only a terminal successful result with final media and a matching usage record establishes end-to-end acceptance.

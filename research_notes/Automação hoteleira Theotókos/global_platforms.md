# Cloudbeds, SiteMinder, STAAH e Omnibees

## Cobertura funcional e documentação oficial

### Takeaway
Cloudbeds é a opção com documentação pública mais acessível para uma integração PMS-first: a API documenta OAuth 2.0, sandbox, reservas, hóspedes, disponibilidade, tarifas, check-in/out e webhooks. SiteMinder oferece uma família de APIs com semânticas distintas para canais, PMS/RMS, reservas e venda direta. STAAH e Omnibees expõem capacidades relevantes de distribuição, mas parte importante da documentação técnica depende de onboarding, credenciais ou relacionamento comercial. ([Cloudbeds API](https://www.cloudbeds.com/api/); [Cloudbeds Developer Documentation](https://developers.cloudbeds.com/); [SiteMinder APIs](https://developer.siteminder.com/get-started/siteminder-apis); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf))

### Cited Findings
- **Cloudbeds — verificado:** a API pública é documentada como uma superfície para integrações customizadas e inclui acesso a dados operacionais do PMS; o portal oficial oferece documentação de referência, guias, ambiente de teste e exemplos. ([Cloudbeds API](https://www.cloudbeds.com/api/); [About Cloudbeds APIs](https://developers.cloudbeds.com/docs/about-cloudbeds-api); [PMS API reference](https://developers.cloudbeds.com/reference/about-pms-api))
- **Cloudbeds — reservas e hóspedes, verificado:** a especificação e os exemplos oficiais cobrem criação, leitura, atualização e cancelamento de reservas, além de dados de hóspedes e objetos relacionados à estadia. ([Cloudbeds OpenAPI specs](https://github.com/cloudbeds/openapi-specs); [Cloudbeds Python API](https://github.com/cloudbeds/cloudbeds-api-python))
- **Cloudbeds — tarifas e disponibilidade, verificado:** o ecossistema documenta objetos para disponibilidade de quartos, planos tarifários, restrições e inventário, incluindo integrações de distribuição. ([Cloudbeds integration guide](https://developers.cloudbeds.com/docs/integration-guide.md); [Cloudbeds OpenAPI specs](https://github.com/cloudbeds/openapi-specs))
- **Cloudbeds — check-in/out e eventos, verificado:** a API e a documentação de webhooks cobrem eventos de reservas, hóspedes, check-in e check-out; assinaturas são registradas para um objeto, ação e URL de destino. ([Cloudbeds webhooks](https://developers.cloudbeds.com/docs/webhooks-1); [Cloudbeds API reference](https://developers.cloudbeds.com/reference/about-pms-api))
- **SiteMinder — SiteConnect, verificado:** SiteConnect é a interface para canais e parceiros contratados; a documentação descreve envio de disponibilidade, tarifas e restrições (ARI) e retorno de reservas novas, alteradas e canceladas. ([SiteConnect developer guide](https://developer.siteminder.com/siteconnect-api); [Booking channel integration](https://developer.siteminder.com/get-started/integration-types/booking-channel))
- **SiteMinder — pmsXchange, verificado:** pmsXchange é direcionada a PMS/RMS e documenta sincronização bidirecional de disponibilidade, tarifas, restrições e reservas, inclusive alterações e cancelamentos. ([pmsXchange developer guide](https://developer.siteminder.com/pmsxchange-api))
- **SiteMinder — Channels Plus, verificado:** Channels Plus é uma API REST/JSON para parceiros que precisam pesquisar propriedades, consultar tarifas/disponibilidade e operar reservas por fluxos de lock, confirmação, alteração e cancelamento. ([Channels Plus developer guide](https://developer.siteminder.com/channels-plus-api))
- **SiteMinder — venda direta, verificado:** a Direct Booking API fornece dados de propriedade, tarifas e disponibilidade para experiências de reserva próprias; a documentação separa esse caso de uso das APIs de canal e PMS. ([Direct Booking API](https://developer.siteminder.com/direct-booking-api); [SiteMinder API selection](https://developer.siteminder.com/get-started/api-selection))
- **STAAH — ChannelConnect, verificado:** o portal oficial de API identifica uma interface para conexão de canais e sistemas com dados de propriedade, tipos de quarto, planos tarifários, tarifas, disponibilidade, restrições e reservas. ([STAAH ChannelConnect](https://getapidoc.staah.net/v1/))
- **STAAH — janela de inventário, verificado:** a documentação de integração disponível publicamente descreve leitura de dados para horizontes de 365 dias, podendo chegar a 730 dias em alguns fluxos; a aplicação deve confirmar o limite efetivo no contrato e ambiente recebido. ([STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [STAAH RMS documentation](https://rmsdoc.staah.net/))
- **STAAH — conteúdo e comunicação, verificado com ressalva:** atualizações oficiais do produto mencionam extensões para promoções, conteúdo, comunicação com hóspedes e avaliações; isso não prova que todos os recursos estejam disponíveis para qualquer parceiro ou plano. ([STAAH product update](https://www.staah.com/resources/upcoming-enhancements-to-staah-channel-connect-api/))
- **Omnibees — APIs REST e XML/OTA, verificado:** os recursos públicos associados à plataforma mostram serviços REST e interfaces XML alinhadas a mensagens OTA para operações de PMS/distribuição, incluindo tarifas, inventário, disponibilidade, restrições e reservas. ([Omnibees REST API help](https://omni-rest.services.cvc.com.br/); [Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf); [OmniH BE API v2](https://documenter.getpostman.com/view/479282/SWEB4Gvc))
- **Omnibees — mensagens de distribuição, verificado:** a documentação pública de PMS referencia mensagens OTA para notificações de tarifas, planos tarifários, inventário e disponibilidade, além de fluxos de reserva e resposta. ([Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf); [Omnibees PullWebService](https://pmscert.omnibees.com/OTA2014B/PullWebService.asmx))
- **Omnibees — perfis e check-in/out, gap público:** não foi localizada, nos recursos públicos consultados, uma matriz clara que confirme endpoints independentes para perfil completo do hóspede, check-in, check-out, preferências ou histórico; esses pontos devem ser validados com o documento de integração e sandbox fornecidos ao parceiro. ([Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf); [Omnibees REST API help](https://omni-rest.services.cvc.com.br/))

### Inferences
- Para um apart-hotel pequeno, Cloudbeds ou um PMS conectado a pmsXchange tende a reduzir trabalho de mapeamento porque a documentação pública descreve objetos operacionais; STAAH e Omnibees podem ser adequadas como hubs de distribuição, mas o risco de projeto é maior quando payloads, credenciais e eventos dependem de onboarding. Essa é uma inferência baseada na acessibilidade da documentação, não uma afirmação de qualidade de produto. ([Cloudbeds developers](https://developers.cloudbeds.com/); [SiteMinder pmsXchange](https://developer.siteminder.com/pmsxchange-api); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf))
- O sistema escolhido deve ser contratado com uma matriz explícita de room type, unidade física, plano tarifário, ocupação, impostos/taxas, política de cancelamento, minimum stay, CTA/CTD, stop-sell e allotment; os termos “ARI” e “disponibilidade” não garantem que todos esses campos sejam suportados em cada conector. ([SiteMinder SiteConnect](https://developer.siteminder.com/siteconnect-api); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [Cloudbeds integration guide](https://developers.cloudbeds.com/docs/integration-guide.md))

### Gaps
- Não foi encontrada uma tabela pública comparável de cobertura de guest profile, check-in/out, pagamentos, webhooks, rate limits e SLA para os quatro fornecedores. A ausência deve ser tratada como requisito de due diligence, não como prova de inexistência. ([Cloudbeds Developer Documentation](https://developers.cloudbeds.com/); [SiteMinder Developer Guide](https://developer.siteminder.com/); [STAAH resources](https://www.staah.com/resources/); [Omnibees REST API help](https://omni-rest.services.cvc.com.br/))

## Sincronização bidirecional, webhooks, retries e risco de overbooking

### Takeaway
SiteMinder documenta explicitamente fluxos push/bidirecionais em SiteConnect e pmsXchange. Cloudbeds documenta webhooks orientados a eventos. STAAH documenta combinação de snapshots pull e deltas push, com endpoint de parceiro; Omnibees documenta modelos REST/XML de troca e notificações, mas os detalhes de retry, idempotência e latência não estão expostos de forma comparável. Logo, “tempo real” deve ser convertido em SLA e testes de concorrência. ([Cloudbeds webhooks](https://developers.cloudbeds.com/docs/webhooks-1); [SiteMinder pmsXchange](https://developer.siteminder.com/pmsxchange-api); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf))

### Cited Findings
- **Cloudbeds — verificado:** webhooks são cadastrados por objeto e ação, com uma URL de destino; eventos de criação/modificação de reserva e mudanças de hóspede podem ser usados para atualizar uma aplicação downstream. ([Cloudbeds webhooks](https://developers.cloudbeds.com/docs/webhooks-1))
- **Cloudbeds — verificado:** a política de API informa que excesso de chamadas ou chamadas repetidas pode provocar bloqueio de IP/conta, exigindo tratamento de erro e contato com o fornecedor para desbloqueio. ([Cloudbeds API policies](https://docs.cloudbeds.com/docs/api/policies/#rate-limits))
- **SiteMinder — verificado:** SiteConnect e pmsXchange são interfaces de integração que empurram alterações para o parceiro, enquanto Channels Plus é uma API REST de consulta/operação; a seleção da API depende do papel do integrador. ([SiteMinder API selection](https://developer.siteminder.com/get-started/api-selection); [SiteMinder APIs](https://developer.siteminder.com/get-started/siteminder-apis))
- **STAAH — verificado:** ChannelConnect combina pull para snapshots completos com push para alterações incrementais; as descrições de integração exigem que o parceiro registre endpoints para receber deltas e reservas. ([STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [STAAH RMS documentation](https://rmsdoc.staah.net/))
- **STAAH — verificado:** o parceiro deve mapear quartos e planos tarifários e publicar reservas de volta ao STAAH para manter o inventário sincronizado; o fluxo exige IPs/endpoint previamente registrados. ([STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [STAAH resources](https://www.staah.com/resources/))
- **Omnibees — verificado com escopo limitado:** recursos públicos descrevem autenticação por token e serviços REST/XML com mensagens de atualização e notificações; não foi localizada uma política pública com tentativas, backoff, deduplicação, assinatura de webhook ou p99 de entrega. ([OmniH BE API v2](https://documenter.getpostman.com/view/479282/SWEB4Gvc); [Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf))
- **Brasil — verificado:** a LGPD exige finalidade, necessidade, segurança, prevenção e responsabilização no tratamento de dados pessoais; isso se aplica ao compartilhamento de dados entre PMS, channel manager, motor, gateway e CRM. ([Lei 13.709/2018](https://www.planalto.gov.br/ccivil_03/_ato2015-2018/2018/lei/l13709.htm); [Guia ANPD para pequeno porte](https://www.gov.br/anpd/pt-br/centrais-de-conteudo/materiais-educativos-e-publicacoes/guia-orientativo-sobre-seguranca-da-informacao-para-agentes-de-tratamento-de-pequeno-porte))
- **Comparação brasileira — verificado:** fornecedores brasileiros como Simpleshotel anunciam sincronização bidirecional de disponibilidade, tarifas e reservas com canais, mas a página pública não expõe rate limits, idempotência ou SLA; HSystem descreve envio de tarifas, disponibilidade, políticas e restrições, também sem especificação API pública equivalente. ([Simpleshotel integrações](https://simpleshotel.com.br/integracoes.html); [Simpleshotel funcionalidades](https://simpleshotel.com.br/funcionalidades.html); [HUNIT](https://hsystem.com.br/produtos/hunit-gestor-de-canais/))

### Inferences
- Todo consumidor de webhook deve persistir o evento bruto, responder rapidamente, processar de forma assíncrona, deduplicar por evento/origem/reserva/versão e executar reconciliação periódica por snapshot; essa é uma recomendação de engenharia porque as páginas consultadas não prometem entrega única, ordem global ou exatamente-uma-vez. ([Cloudbeds webhooks](https://developers.cloudbeds.com/docs/webhooks-1); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/))
- Para evitar overbooking, o PMS ou hub deve ser a autoridade única de inventário vendável; o channel manager deve distribuir o resultado e receber reservas, não permitir edições concorrentes sem versionamento. A recomendação decorre da existência de fluxos de atualização de ARI e reservas, não de uma garantia contratual dos fornecedores. ([SiteMinder pmsXchange](https://developer.siteminder.com/pmsxchange-api); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [Cloudbeds integration guide](https://developers.cloudbeds.com/docs/integration-guide.md))
- O aceite deve medir p95/p99 de atualização, tempo de propagação de stop-sell, duplicação/ordem de eventos, falha de endpoint, timeout, retry, alteração simultânea e reabertura de disponibilidade; “real-time” sem número de SLA não é suficiente para uma propriedade com poucas unidades. ([SiteMinder SiteConnect](https://developer.siteminder.com/siteconnect-api); [Cloudbeds API policies](https://docs.cloudbeds.com/docs/api/policies/#rate-limits))

### Gaps
- Não foram localizados, em páginas públicas consultadas, números comparáveis de latência, política de retry, backoff, dead-letter queue, idempotency key ou garantia de entrega para Cloudbeds, SiteMinder, STAAH e Omnibees. Esses campos devem ser pedidos em contrato, sandbox e runbook de incidente. ([Cloudbeds API policies](https://docs.cloudbeds.com/docs/api/policies/#rate-limits); [SiteMinder Developer Guide](https://developer.siteminder.com/); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf))

## Adequação operacional, acesso, custos ocultos e recomendação para Theotókos

### Takeaway
Para uma pequena propriedade brasileira, a decisão não deve ser “qual tem mais canais”, mas “qual documenta e suporta os estados que a equipe consegue operar”: tarifa e restrições, inventário por tipo de unidade, reserva completa, alterações/cancelamentos, perfil de hóspede, check-in/out, reconciliação e suporte de incidente. Cloudbeds oferece o caminho público mais direto para desenvolvimento; SiteMinder é forte quando o projeto precisa de uma API de distribuição/PMS claramente separada; STAAH e Omnibees devem ser avaliadas com acesso de parceiro e testes reais antes da compra. ([Cloudbeds API](https://www.cloudbeds.com/api/); [SiteMinder API selection](https://developer.siteminder.com/get-started/api-selection); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf))

### Cited Findings
- **Cloudbeds — verificado:** o fornecedor divulga API aberta, marketplace de integrações, onboarding/migração e conectores para distribuição e operações; a documentação pública também oferece material para parceiros e desenvolvedores. ([Cloudbeds hotel management](https://www.cloudbeds.com/hotel-management-software/); [Cloudbeds developers](https://developers.cloudbeds.com/))
- **SiteMinder — verificado:** a documentação exige escolher a API conforme o tipo de integração — canal, PMS/RMS, dados de reserva, ou venda direta — e oferece contato/fluxos de onboarding para integração. ([SiteMinder get started](https://developer.siteminder.com/get-started); [SiteMinder contact](https://developer.siteminder.com/contact))
- **STAAH — verificado:** os recursos de API e conexão são publicados em portais específicos e o acesso operacional exige registro de endpoint, IP e mapeamento; isso indica dependência de onboarding técnico. ([STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [STAAH RMS documentation](https://rmsdoc.staah.net/))
- **Omnibees — verificado:** há documentação pública de serviços REST/XML e exemplos de mensagens, porém o material consultado recomenda relacionamento técnico/credenciais para obter a especificação atual e ambiente de teste. ([Omnibees REST API help](https://omni-rest.services.cvc.com.br/); [OmniH BE API v2](https://documenter.getpostman.com/view/479282/SWEB4Gvc))
- **Brasil — verificado:** a ANPD recomenda controles de acesso, proteção de armazenamento, segurança de comunicações, gestão de vulnerabilidades, contratos e treinamento para agentes de pequeno porte; isso é diretamente relevante ao intercâmbio de perfis de hóspedes e documentos. ([Guia ANPD para pequeno porte](https://www.gov.br/anpd/pt-br/centrais-de-conteudo/materiais-educativos-e-publicacoes/guia-orientativo-sobre-seguranca-da-informacao-para-agentes-de-tratamento-de-pequeno-porte))
- **Brasil — verificado:** a LGPD reconhece direitos de acesso, correção, eliminação de dados desnecessários e informação sobre compartilhamentos; o contrato deve prever exportação, assistência a titulares, retenção e eliminação. ([LGPD art. 18](https://www.planalto.gov.br/ccivil_03/_ato2015-2018/2018/lei/l13709.htm); [ANPD direitos dos titulares](https://www.gov.br/anpd/pt-br/assuntos/titular-de-dados/direito-dos-titulares))

### Inferences
- **Shortlist inicial:** Cloudbeds deve ser priorizada se Theotókos quer construir uma integração própria ou combinar PMS, channel manager, pagamentos e operações por APIs; SiteMinder deve ser priorizada se o objetivo principal é distribuição e sincronização ARI/reservas entre PMS/RMS/canais; STAAH e Omnibees devem permanecer em shortlist condicionada a sandbox, documentação completa e prova de cobertura de hóspedes/check-in/out. ([Cloudbeds developers](https://developers.cloudbeds.com/); [SiteMinder pmsXchange](https://developer.siteminder.com/pmsxchange-api); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf))
- **Pacote mínimo de contratação:** exigir sandbox, credenciais de produção separadas, lista de eventos, payloads, versionamento, limites, retries, janela de manutenção, SLA, suporte de incidente, exportação, suboperadores, residência/transferência internacional, retenção e responsabilidade financeira por overbooking. Essa lista é uma recomendação derivada das lacunas públicas, não uma promessa dos fornecedores. ([Cloudbeds API policies](https://docs.cloudbeds.com/docs/api/policies/#rate-limits); [SiteMinder Developer Guide](https://developer.siteminder.com/); [Guia ANPD](https://www.gov.br/anpd/pt-br/centrais-de-conteudo/materiais-educativos-e-publicacoes/guia-orientativo-sobre-seguranca-da-informacao-para-agentes-de-tratamento-de-pequeno-porte))
- **Piloto recomendado:** usar reservas anonimizadas e testar criação, alteração de datas/ocupação, troca de unidade, cancelamento/no-show, stop-sell, bloqueio de manutenção, falha de webhook, duplicação, reprocessamento e reconciliação; liberar produção apenas quando o estado final coincidir no PMS, hub, canal e operação. ([Cloudbeds webhooks](https://developers.cloudbeds.com/docs/webhooks-1); [SiteMinder pmsXchange](https://developer.siteminder.com/pmsxchange-api); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/))
- **Check-in/out e guest profile:** não presumir paridade entre vendors. Cloudbeds documenta esses objetos explicitamente; para SiteMinder, STAAH e Omnibees, as APIs consultadas são principalmente de distribuição e reserva, então o PMS de autoridade pode precisar continuar responsável por perfil, check-in, check-out, folio e exigências locais. ([Cloudbeds PMS API reference](https://developers.cloudbeds.com/reference/about-pms-api); [SiteMinder APIs](https://developer.siteminder.com/get-started/siteminder-apis); [STAAH ChannelConnect](https://getapidoc.staah.net/v1/); [Omnibees PMS documentation](https://pmscert.omnibees.com/OTA2014B/Doc/PMSOmnibees.pdf))

### Gaps
- Não foi localizada documentação pública específica sobre suporte operacional local no Brasil, preços por número de unidades, atendimento em português, integração fiscal/FNRH, Pix, NFSe/NFCe, canais brasileiros, responsabilidade por overbooking ou tempos de resposta de suporte para os quatro fornecedores. Esses itens devem ser confirmados com proposta comercial e referências brasileiras. ([Cloudbeds hotel management](https://www.cloudbeds.com/hotel-management-software/); [SiteMinder](https://www.siteminder.com/); [STAAH](https://www.staah.com/); [Omnibees](https://www.omnibees.com/))
- Não foi encontrada, nesta pesquisa, uma comparação independente brasileira que audite latência, taxa de falhas ou cobertura de campos entre Cloudbeds, SiteMinder, STAAH e Omnibees. Fontes brasileiras de comparação devem ser usadas como contexto comercial, não como substituto dos testes de integração. ([Hotelier News](https://www.hoteliernews.com.br/); [Panrotas](https://www.panrotas.com.br/))
